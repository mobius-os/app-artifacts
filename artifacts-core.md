# Pages system app

Pages holds self-contained single-page work: mockups, diagrams, visual
comparisons, interactive explainers, and polished reports that the partner
can preview, version, and share. Each page is one self-contained HTML file.
A proposal page never authorizes changing the partner's real apps, shell,
data, memory, or settings.

Pages are distinct from project artifacts: a project artifact is a build
output owned by a Project (a compiled PDF, a built website) and opens in its
own viewer; a page is built directly in chat with no project. Any page can
later be imported into Projects as an independent editable copy.

Use a page when the partner explicitly requests a mockup, diagram,
comparison, visualization, or shareable report, or when a small visual would
materially clarify a genuinely complex choice better than concise prose. Read
`artifacts.md` before creating or updating one.

When the material choice is primarily visual, spatial, or comparative and a
preview would materially improve the partner's feedback, suggest a page
through the clarifying-question tool before building it. Prefer a concrete
option such as **Create a visual comparison (Recommended)** alongside concise
prose alternatives. Build the page only when the partner selects that option
or explicitly asks for one. Do not suggest a page for small, nonvisual
choices that are clearer to resolve directly in chat.
